## 2. 代码分析（按链路）

### 2.1 公共模块 soms-common

- **统一返回**：`Result<T>`（code/message/data）+ `ResultGenerator` + `ResultCodeMessage` 枚举（0 成功 / 400 业务失败 / 401 参数错误 / 403 锁定 / 404 / 500 / 501 / 502）。
- **分页**：`PageResult<T>`（records/total/size/current/pages），与 MyBatis-Plus `Page` 字段一致，可互相反序列化。
- **Feign 客户端**：
  - `AdminUserFeignClient`（path=`/api/v1/admin/internal`）→ 登录时查角色权限；
  - `CustomerFeignClient`（path=`/api/v1/customer`）→ 后台查客户列表。
- **JWT 工具**：HS256，claims 含 userId / userType / roles / tokenVersion；`createRefreshToken` 为 UUID。
- **UserContext**：从 `X-User-Id` / `X-User-Type` / `X-Roles` 三个 header 读取用户上下文（网关透传）。
- **MyBatis-Plus 配置**：分页插件（MySQL）+ `MyMetaObjectHandler` 自动填充 gmtCreate/gmtModified。
- **JwtProperties**：`@RefreshScope` + Nacos 动态刷新。

### 2.2 网关 soms-gateway（80）

- 路由：`/api/v1/auth/**` → service-auth；`/api/v1/admin/**` → service-admin；`/api/v1/customer/**` → service-customer；`/api/v1/store/**` → service-store（后两个路由已配，store 服务尚无接口）。
- `AuthGlobalFilter`（order=-100）：白名单放行 → 解析 JWT → 查 Redis 黑名单 → **生成网关签名**（HMAC-SHA256：`userId|userType|roles|timestamp`，±5 分钟窗口）→ 注入 `X-User-Id` / `X-User-Type` / `X-Roles` / `X-Gateway-Timestamp` / `X-Gateway-Sign` → 转发。
- 白名单：`/api/v1/auth/login`、`/api/v1/auth/refresh`、`/api/v1/auth/sms/send`（**尚未实现**）、`/api/v1/customer/auth/**`（**尚未实现**）、`/actuator/**`、`/favicon.ico`。
- 失败统一返回：HTTP 401 + `{"code":401,...}`。

### 2.3 认证服务 soms-auth-service（8100）

- **登录**：按 userType+username 查 `auth_account` → 校验状态（1 正常）→ BCrypt 校验密码 → 管理员/员工经 Feign 调 admin 获取 roles/permissions/dataScope/storeIds → 权限写入 Redis `auth:perms:{userId}`（permissions/dataScope/storeIds，TTL=token 有效期）→ 签发 accessToken（管理员/员工 8h，会员 7d）→ 生成 refreshToken 入库 → 更新 lastLogin → 写登录日志。
- **登出**：accessToken 加入 Redis 黑名单，TTL=剩余有效期。
- **刷新**：校验 refresh_token 表（status=1 且未过期）→ 签发新 accessToken。
- 失败场景均写 `auth_login_log`。

### 2.4 后台管理 soms-admin-service（8000）

- **RBAC 数据模型**：`sys_admin`（管理员）/ `sys_employee`（员工）/ `sys_role`（角色）/ `sys_permission`（权限）/ 关联表 `sys_admin_role`、`sys_employee_role`、`sys_employee_store`、`sys_role_permission`。
- **角色接口**：分页 / 详情 / 新增 / 修改 / 删除（逻辑删 + 清关联）/ 分配权限（先清空再插入）。
- **权限接口**：权限树（status=1，按 sort 排序，parentId 为根）、角色已分配权限 ID。
- **内部接口** `/api/v1/admin/internal/user-auth`：按 userId+userType 查角色权限；`SUPER_ADMIN` 返回全量权限、dataScope=1；员工额外返回可管 storeIds；会员/供应商返回空权限、dataScope=4。
- **Security 链路**：`GatewayAuthFilter`（OncePerRequestFilter）先校验网关签名（时间戳 ±5min + HMAC-SHA256 常量时间比较）→ 从 Redis 加载权限 → 组装 `SimpleGrantedAuthority`（权限编码 + `ROLE_角色编码`）→ 写入 SecurityContext → `@PreAuthorize("hasAuthority('xxx')")` 生效。
- **客户列表**：`/api/v1/admin/customer/list` 经 Feign 调 customer 服务分页查询（需权限 `customer:list`）。
- **Nacos 状态**：`/api/v1/admin/nacos/server/status` 拉取注册中心全部服务实例。

### 2.5 客户服务 soms-customer-service（8010）

- 客户 CRUD：新增（手机号唯一校验 + 默认值）/ 逻辑删除 / 更新（手机号冲突校验）/ 按 ID 查 / 按手机号查 / 分页模糊查询（姓名+手机号）。
- 手写 XML mapper（`CustomerMapper.xml`）+ BaseMapper 混用；`schema.sql` 提供 `soms_customer` 库建表脚本（含 uk_mobile 唯一索引）。

### 2.6 其余服务

- store：已有 Store / StoreRegion 实体与 mapper、元数据填充，**无 Controller / Service**。
- product / stock / order / pay / discount-calculation / finance / self-checkout：仅 `@EnableDiscoveryClient + @SpringBootApplication` 启动类，无任何业务代码。

## 4. 发现的问题清单（按严重度）

### 🔴 高优先级（阻塞测试/上线）

| # | 问题 | 位置 | 说明与建议 |
|---|---|---|---|
| 1 | **数据库脚本缺失** | 全项目 | 只有 `soms_customer` 建表脚本；`auth_account`、`auth_login_log`、`auth_refresh_token`、`sys_*` 共 9 张表**均无 DDL**，也没有种子数据（admin 账号、SUPER_ADMIN 角色、权限数据）。登录链路无法落地。**建议：补齐 auth/admin 建表 SQL + 初始化数据脚本，纳入版本库。** |
| 2 | **Nacos 配置内容不在仓库** | 各服务 yml | 依赖 `soms-common.yml`（含 datasource、jwt.secret）、`soms-redis.yml`、`service-*.yml`（含 gateway.sign.secret）等 Nacos 配置，但仓库中无这些配置的内容，也没有导出/备份。换机器即无法启动。**建议：提供 Nacos 配置模板文件（脱敏）进仓库 docs 或 config 目录。** |
| 3 | **customer 服务 Nacos 配置导入非 optional** | customer application.yml | `config.import` 用的是 `nacos:...`（非 `optional:nacos:...`），Nacos 配置中心不可用时**直接启动失败**；其余服务均用 optional。**建议：统一为 optional。** |
| 4 | **端口冲突与文档不一致** | order/product/auth 的 yml + docs | order 与 product 同为 8090；docs 中 auth 为 8090 而实际 8100。**建议：重新分配端口（如 product 8080），并修正文档。** |

### 🟡 中优先级（逻辑缺陷）

| # | 问题 | 位置 | 说明与建议 |
|---|---|---|---|
| 5 | **角色管理抛 RuntimeException** | SysRoleServiceImpl | “角色编码已存在/角色不存在”抛出 `RuntimeException`，被全局兜底处理为 **500**，而文档约定为业务异常 **400**。**建议：改抛 `BusinessException`。** |
| 6 | **refresh 后 token 丢失 roles** | AuthServiceImpl.refresh | 刷新签发 accessToken 时 roles 传 `Collections.emptyList()`，新 token 中无角色 → 网关透传的 `X-Roles` 为空 → 依赖 `ROLE_` 前缀的权限判断失效（当前 `@PreAuthorize` 用权限编码，靠 Redis 缓存还能兜底，但属隐患）。**建议：refresh 时重新查角色并写入 token 与 Redis 缓存。** |
| 7 | **客户服务无权限控制** | customer 服务 | 客户 CRUD 接口经网关路由后**任何已登录用户都可调用**，未加权限校验；直接访问 8010 端口也无任何认证（无网关签名校验过滤器）。**建议：customer 服务补充网关签名校验过滤器 + 接口权限注解，或由 admin 服务代理管控。** |
| 8 | **权限缓存无 DB 兜底** | PermissionCacheService | 若 Redis 中 `auth:perms:{userId}` 过期/被清，已登录用户会突然失去全部权限。**建议：缓存 miss 时回源查库（Feign 调 admin 内部接口）并回填。** |
| 9 | **`/internal/**` 无实际防护** | admin InternalUserController | 文档称内部接口“只允许内网访问、网关不路由”，但当前网关路由 `Path=/api/v1/admin/**` 会匹配 `/api/v1/admin/internal/**`，**并没有排除 internal 路径**；且 admin 端口无 ACL。**建议：网关路由排除 `/api/v1/admin/internal/**`，并加 IP 白名单或内部鉴权头。** |

## 5. 后续开发建议（路线图）

### 阶段 0（立即，1~2 天）：可运行、可测试
1. 补齐 **auth/admin 建表 SQL + 种子数据**（默认 admin/SUPER_ADMIN、权限字典）。
2. 提供 **Nacos 配置模板**（soms-common/soms-redis/service-*.yml）并落地到本地 Nacos。
3. 修复高优先级问题 #3、#4（optional 配置、端口冲突）。
4. 统一端口：建议 `product=8080`、`order=8090`、`auth=8100`，文档同步修正。

### 阶段 1（3~5 天）：核心业务最小闭环
1. **门店服务**（store）：已有实体，补齐 Region/Store CRUD + 分页 + 数据权限（dataScope 落地：区域/门店维度过滤）。
2. **商品服务**（product）：商品 SPU/SKU 模型、分类、上下架；建表脚本 + DDL。
3. **库存服务**（stock）：出入库、库存查询、库存调整，与商品服务联调。
4. **订单服务**（order）：下单、订单明细、取消；状态机设计先行。

### 阶段 2（5~10 天）：交易闭环
1. **自助收银**（self-checkout）：购物车、结算、优惠计算调用。
2. **折扣计算**（discount-calculation）：会员等级折扣、促销规则引擎。
3. **支付**（pay）：支付单、回调、退款（先接模拟支付）。
4. **财务**（finance）：对账、报表（对接订单+支付流水）。

### 阶段 3（持续）：工程化与质量
1. **统一异常/错误码规范**：所有服务统一使用 common 的 BusinessException + ResultCodeMessage。
2. **日志链路**：引入 TraceId（MDC）贯穿网关→服务，日志集中采集。
3. **数据权限中间件**：按 dataScope 自动注入门店过滤条件（MyBatis-Plus 拦截器）。
4. **分布式事务/最终一致性**：下单→扣库存→支付场景引入 Seata 或本地消息表。
5. **单元测试/接口测试**：为已实现接口补齐自动化测试（见接口文档测试章节）。
6. **前端**：管理后台（Vue/React）+ 自助收银端，接网关统一鉴权。

### 架构层面的建议
- **API 版本管理**：现有 `/api/v1` 前缀合理，保持。
- **内部接口与外部接口分离**：尽快把 `/internal/**` 从网关路由中排除，并增加内部鉴权。
- **配置管理**：密钥类配置（JWT_SECRET / GATEWAY_SIGN_SECRET / 数据库密码）必须走 Nacos + 环境变量，禁止入库。
- **DTO 收口**：customer 服务目前直接返回实体 `Customer`，建议统一走 DTO（common 中已有 CustomerDTO），避免内部表结构外泄。
