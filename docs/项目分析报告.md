## 3. 核心交易链路现状

**结论：核心交易链路（认证 → 商品 → 库存 → 优惠 → 订单 → 支付）已端到端打通，可直接进入联调。**

以订单服务 [OrderServiceImpl](file:///D:/Idea_item/SOMS-2026-1012/soms-server/soms-order-service/src/main/java/com/mfnit/order/service/impl/OrderServiceImpl.java)（508 行）为编排中心，下单流程已实现：

1. 经 `StoreFeignClient` 校验门店存在且营业（businessStatus=2）；
2. 经 `ProductFeignClient` 逐个校验商品存在且上架（status=1），构建购物车行；
3. 经 `DiscountFeignClient` 调用优惠计算，得到原价/优惠/应付金额；
4. 预生成订单 ID + 订单号，经 `StockFeignClient.lock` 锁库存；
5. 若有券则 `lockCoupon`，**锁券失败时回滚释放库存**（含二次异常兜底日志）；
6. 落库订单主表 + 明细 + 状态日志（`@Transactional`）。

优惠计算引擎（`DiscountEngine` 307 行 + 6 个计算器）已实现：**满减 / 折扣 / 一口价 / N 件折 / 阶梯减 / 买赠**，并支持规则、促销、优惠券、价签、定时任务。

**已知薄弱环节**：
- 跨服务一致性完全依赖 Feign 同步调用 + 本地 `@Transactional`，除锁券外无统一的补偿/Saga/最终一致性兜底（下单→扣库存→支付场景仍有一致性风险）。
- 支付渠道尚未接真实第三方（见 §4）。

## 6. 分层结论与后续建议

### 6.1 分层结论

- **第一梯队（可直接联调）**：优惠计算、商品、订单、后台管理、common。
- **第二梯队（核心可用、需补全）**：支付（缺真实渠道）、客户、库存、门店、认证、网关。
- **第三梯队（未启动）**：财务服务、自助收银服务。
- **全局短板**：测试缺失、支付渠道 mock、跨服务一致性缺少统一兜底。

### 6.2 建议优先级

1. **替换支付 mock（最高）**：接通 customer 余额扣减真实接口，对接微信/支付宝付款码与退款回调。
2. **补齐空壳模块**：财务（对账/流水/报表，基于订单+支付）、自助收银（购物车/结算，复用优惠引擎与订单编排）。
3. **强化一致性**：下单→锁库存→支付引入本地消息表 / Seata / Saga，覆盖当前仅「锁券失败回滚」的不足。
4. **补测试**：优先为订单编排、优惠引擎、支付流程写单测与契约测试。
5. **扩展库存/客户**：库存补入库/调拨/盘点；客户补会员等级、积分规则等文档已承诺能力。
